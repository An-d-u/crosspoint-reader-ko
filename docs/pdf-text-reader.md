# PDF 텍스트 읽기

PDF의 텍스트 또는 숨김 OCR 텍스트를 기기에서 추출한 뒤 TXT와 같은 EPUB 페이지 엔진으로 다시 배치한다. 원본 페이지를 축소해서 그리는 PDF 뷰어가 아니며, 기기 자체 OCR도 수행하지 않는다.

## 사용 방법

1. SD 카드에 `.pdf` 파일을 복사하거나 Wi-Fi 파일 전송으로 업로드한다.
2. 파일 탐색기에서 PDF를 연다. 첫 실행에는 텍스트 추출과 페이지 캐시 생성 시간이 필요하다.
3. 생성된 페이지는 기존 글꼴·줄 간격 설정, 페이지 이동, 진행률 및 북마크 경로를 사용한다. 페이지 번호는 원본 PDF 페이지 번호가 아니라 재배치된 독서 페이지 번호다.

원본 파일은 변경하지 않는다. 글꼴 등 페이지 배치 설정이 바뀌어 캐시를 다시 만들면 PDF 추출도 다시 수행한다. 설정 변경 후 북마크가 가리키는 페이지의 내용은 달라질 수 있다.

## 첫 버전의 지원 범위

- 일반 상호참조 표(classic xref)와 `/Prev`로 연결된 증분 저장.
- 페이지 트리 순서, 상속된 글꼴 리소스, 여러 본문 스트림.
- 무압축 또는 Flate 압축된 본문과 문자표.
- `ToUnicode`의 `bfchar` 및 `bfrange`를 통한 한글·일본어·유니코드 변환.
- 단순 Type1/TrueType 글꼴의 WinAnsi, 또는 기본 ASCII 문자.
- `Tj`, `TJ` 등 텍스트 출력 명령과 숨김 OCR 텍스트. OCR 배경 이미지는 읽지 않고 건너뛴다.

텍스트 순서는 PDF에 기록된 출력 명령 순서를 따른다. 원본 글꼴·강조·색·표·이미지는 재현하지 않으며, 다단 편집·세로쓰기·낱글자 단위 배치에서는 읽기 순서나 띄어쓰기가 원본과 달라질 수 있다. OCR이 되어 있어도 문자표 또는 내부 구조가 지원 범위 밖이면 열리지 않는다.

다음 항목은 오류 안내 후 종료한다.

- 암호화된 문서, xref 스트림·압축 객체, Form XObject 또는 인라인 이미지.
- 지원하지 않는 압축 필터·예측기·외부 CMap 또는 해석할 수 없는 문자 인코딩.
- 텍스트 없는 문서 또는 이미지가 있지만 텍스트가 없는 페이지. 일부 페이지만 빠진 문서를 성공으로 표시하지 않는다.
- 손상된 구조·압축 체크섬, SD 입출력 오류, 메모리 또는 처리 한도 초과.

이미지 전용 PDF를 통째로 표시하는 기능은 포함하지 않는다. 이를 구현하려면 별도 PDF 렌더러 또는 PC에서 페이지 이미지로 변환하는 경로가 필요하다.

## 자원 및 안정성

`lib/PdfText/PdfTextParser.h`는 구조·문자표·텍스트 해석을, `PdfText.cpp`는 SD 입출력과 압축 해제를 담당한다. 전체 파일이나 전체 압축 해제 결과를 RAM에 올리지 않는다.

- 원본 최대 512 MiB, 개별 압축 해제 스트림 최대 4 MiB, 누적 스트림 처리 최대 32 MiB.
- 추출 텍스트 최대 16 MiB, 페이지 최대 10,000개, 페이지 트리 최대 24단계.
- 문자표 최대 4,096개 항목, 단일 토큰 최대 4,096바이트, 객체 중첩 최대 8단계.
- 주요 할당 전에 남은 힙과 최대 연속 메모리를 검사한다. 부족하면 캐시 생성을 중단한다.
- 페이지 트리 순회와 압축 버퍼를 힙에 배치해 작은 렌더 작업 스택 사용을 줄인다.
- `pdf-content.tmp`, `pdf-cmap.tmp`, `pdf-text.tmp`를 기존 도서 캐시 디렉터리에서 사용한다. 정상 종료와 처리 실패 시 제거한다. 전원 차단으로 남은 파일은 다음 추출에서 덮어쓴다.

같은 글꼴 문자표의 반복 해석도 누적 처리 한도에 포함한다. 큰 문서는 파일 크기보다 내부 구조 때문에 한도에 먼저 도달할 수 있다.

## 검증

```text
python test/reader/verify_pdf_text.py
python test/reader/verify_text_document.py
python test/reader/generate_pdf_fixtures.py --font <한글-TTF-경로> --japanese-font <일본어-TTF-경로>
python test/reader/verify_pdf_runtime.py --emsdk <Emscripten-도구모음-경로>
```

정적 검증은 실제 C++ 해석기의 토큰·문자표·페이지 순서·텍스트 명령·오류 경로를 실행한다. 런타임 검증은 실제 추출기와 uzlib을 WebAssembly로 빌드하고 8 KiB 스택 제한에서 합성 PDF 7종을 확인한다. 추출 결과 대조, 원본 보존, 실패 결과 및 임시 파일 제거도 검사한다. 생성용 Python에는 ReportLab, Pillow, pypdf가 필요하며, 런타임 검증에는 Python과 Node를 포함하는 Emscripten 도구모음이 필요하다.

합성 PDF와 렌더링 이미지는 `tmp/pdfs/reader/`에 생성하며 커밋하지 않는다. 호스트 검증은 실제 기기에서의 메모리 단편화·속도·표시 품질을 보장하지 않으므로 실기기 확인이 추가로 필요하다.

구조와 텍스트 명령의 기준: [Adobe에서 제공하는 PDF 1.7 명세](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf)의 7.5절, 9.4절, 9.10절.
