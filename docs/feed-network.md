# 피드 네트워크 수신과 진단

GeekNews 목록은 공식 Atom 피드, Hacker News 목록은 Algolia API를 사용한다.
기사 본문은 두 소스 모두 Jina Reader에서 Markdown으로 변환한다. 따라서 목록이 열려도
본문 변환 서버와의 연결이나 원본 사이트의 접근 제한 때문에 기사 열기가 실패할 수 있다.

## 분할 수신 보완

설치된 Arduino 프레임워크의 `NetworkClient::readBytes()`는 `read()`가 음수이면 즉시 반환한다.
그러나 `NetworkClientSecure::read()`는 연결이 살아 있어도 현재 읽을 데이터가 없으면 `-1`을 반환한다.
HTTP 청크 뒤의 `\r\n`이 따로 도착하면 두 바이트를 모두 기다리지 않고 짧은 읽기로 실패할 수 있다.

피드 전용 `FeedSecureClient`는 이 경우 마지막 수신 이후 제한 시간까지 기다린다.
연결이 종료되면 짧은 읽기를 반환하고, 제한 시간을 초과하면 연결을 종료한다.
HTTP 헤더·청크 해석은 계속 Arduino `HTTPClient`가 담당한다. 다른 네트워크 기능의 클라이언트는 바꾸지 않는다.

기사 본문은 SD 임시 파일로 스트리밍하며, 완전 수신과 저장 성공을 확인한 뒤에만 표시한다.
GeekNews의 줄 길이 제한은 HTTP 수신 블록 크기가 아니라 실제 줄에 적용한다.
본문 48 KiB, 한 줄 4 KiB 제한은 유지한다. 잘린 응답을 정상 기사로 취급하지 않는다.

현재 공개 읽기 요청의 TLS 인증서 검증 생략 설정은 기존대로 유지되어 있다.
암호화는 사용하지만 서버 신원을 검증하지 않으므로, 인증된 연결과 동일한 보안을 제공하지 않는다.

## 실패 화면의 진단 값

오류 설명 아래에 마지막 요청의 진단 값이 표시된다. 예를 들어 `B -11 | 2048/-1 B | 60s T`는
본문 단계에서 2,048바이트를 받은 후 시간 초과한 경우를 뜻한다.

- `H`: 연결·요청·응답 헤더 단계, `B`: 응답 본문 단계
- 다음 숫자: HTTP 상태 코드 또는 Arduino HTTPClient의 음수 오류 코드
- `수신량/예상량 B`: 저장 처리기에 전달한 바이트 수와 Content-Length. `-1`은 서버가 길이를 알리지 않은 경우
- `s`: 해당 요청의 경과 시간. 자동 재시도 전체 시간이 아니다.
- `S`: 본문 처리기 또는 저장 실패, `T`: 보완된 본문 읽기의 시간 초과

기사 전체의 실패 여부는 위쪽 오류 설명을 기준으로 한다. 예를 들어 수신은 성공했어도 이후
Markdown 처리나 SD 파일 읽기가 실패하면 진단 값은 HTTP 200을 표시할 수 있다.
SSID, 암호, 기사 URL과 본문은 진단 값에 포함하지 않는다.

## 검증

```powershell
python test/network/verify_feed_transport.py
python test/config/verify_geeknews_feature.py
python -m platformio run -e default
```

첫 테스트는 C++17 컴파일러의 `static_assert`로 실제 수신 함수를 평가한다.
분할된 구분자, 수정 전 조기 반환 재현, 수신 진행에 따른 대기 시간 갱신, 연결 종료,
무응답 제한 시간, 빈 읽기, 32비트 시계 순환을 확인한다. 호스트 컴파일러가 없으면 설치된
PlatformIO RISC-V 컴파일러를 사용하며 테스트용 바이너리를 기기에서 실행할 필요는 없다.

이 테스트와 빌드만으로 실제 Wi-Fi/TLS 연결의 안정성을 보장하지는 않는다.
전체 플래시 후 두 소스의 여러 기사와 재시도를 확인하고, 실패하면 진단 줄까지 포함한 화면을 확인한다.
