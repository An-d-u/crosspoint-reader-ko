# 외부 글꼴 assets 파티션

한국어·일본어 글꼴의 메트릭과 커닝 정보는 앱에 유지하고, 큰 비트맵 데이터만 내장 플래시의 `assets` 파티션에 저장한다. 여기서 외부는 별도 메모리 장치가 아니라 실행 앱 이미지 바깥의 전용 데이터 파티션을 뜻한다.

## 플래시 배치

| 주소 | 내용 |
| --- | --- |
| `0x000000` | 부트로더 |
| `0x008000` | 파티션 테이블 |
| `0x010000` | 8MiB 앱 파티션 |
| `0x810000` | 글꼴 `assets` 파티션 |
| `0xFF0000` | 코어 덤프 |

PlatformIO 빌드는 다음 파일을 생성한다.

- `firmware.bin`: 앱만 포함한다. 단독 설치용이 아니다.
- `assets.bin`: 글꼴 비트맵과 64바이트 검증 헤더를 포함한다.
- `firmware-full.bin`: 부트로더, 파티션 테이블, 앱, 글꼴 assets를 포함하는 16MiB USB 플래시 이미지다.

전체 이미지는 다음과 같이 기록한다.

```bash
esptool.py --chip esp32c3 --port <PORT> --baud 921600 write_flash 0x0 .pio/build/default/firmware-full.bin
```

별도의 `erase_flash` 명령은 필요하지 않다. 다만 16MiB 전체 이미지는 NVS 위치에도 `0xFF`를 포함하므로 플래셔가 전체 범위를 기록하면 저장된 설정과 Wi-Fi 정보가 초기화될 수 있다. 설정을 보존해야 하는 개발 업로드에서는 앱과 `assets.bin`만 각각의 주소에 기록해야 한다.

## 런타임 동작

부팅 시 `assets` 헤더의 매직 값, 버전, 크기와 각 글꼴의 FNV-1a 체크섬을 검사한다. 검증에 성공하면 필요한 글리프 주변 4KiB를 고정 캐시에 유지한다. 전체 글꼴을 MMU에 매핑하지 않으므로 앱이 커져도 글꼴 때문에 MMU 페이지가 고갈되지 않는다.

파티션이 없거나 손상된 경우 외부 글꼴을 등록하지 않고 펌웨어에 남아 있는 Pretendard UI 글꼴을 사용한다. 따라서 글꼴 assets 오류만으로 부팅이 중단되지는 않는다.
